## Ranked corroborated defects

### 1. (S1) A documented injectivity guarantee that the code does not provide, with no downstream check

This is the highest-severity shape this method can produce: an absolute-language promise in the prose,
a reproduced violation in the code, and the two lenses arriving at it blind from opposite directions.

> **Lens B** (`sweep_parser.py:687`, filed as `S12b-B-07`, listed in B's "Absolute-language statements"
> table under **never**):
> "Any swept key without a curated slot in the name (i.e. not in ``_NAMED_RUN_NAME_KEYS``) gets a
> generic ``_{key}{value}`` suffix **so distinct combinations never collapse onto the same folder
> name**."
> …and B's own internal-contradiction list, item 4: "*'never collapse' vs a many-to-one sanitiser* …
> the documented mapping is not injective (`"my run"` and `"my_run"` both → `my-run`)."

> **Lens A** (§2, "The naming function is where this slice breaks"):
> ```
> 761        for key in sorted(swept_keys):
> 762            if key in _NAMED_RUN_NAME_KEYS or key not in params:
> 763                continue
> ```
> "For those seven keys the *only* disambiguation is the lossy base-name encoding, and there is **no
> fallback** if that encoding loses information. It does, in four independent ways" —
> `int(alpha)` (`:742`), `int(round(sfe*100)):03d` (`:728`), `f"{mantissa:.2g}e{exp}"` (`:823`),
> `int(round(omega))` (`:747`) — with a reproduction: `densPL_alpha [-2.0,-1.5,-1.0,-0.5,0.0]` →
> `_PL-2, _PL-1, _PL-1, _PL0, _PL0`, "**3 distinct names for 5 combinations**".

**Adjudication.** The guarantee's *stated mechanism* covers only non-curated keys; the guarantee's
*stated scope* is universal ("distinct combinations"). Both scopes are violated:

- **Within the stated mechanism** — B derived the sanitiser collision from prose alone; A derived the
  identical collision from `_SAFE_VALUE_CHARS_RE.sub('-', …)` alone. Corroborated.
- **Outside it, in the curated set** — A's four lossy encodings. And the suppression that makes them
  unrecoverable is *deliberate*: B independently transcribes the self-test assertion "*A curated key
  passed in swept_keys must NOT be double-encoded*" (`:953`) and the exemption comment (`:587`). So
  the injectivity promise was never backed for the seven curated keys, by design.
- **A fifth path** (A only): a `dens_profile` value that is neither `densPL` nor `densBE` adds no
  token *and* is exempt from the generic suffix — every such combination gets one identical name.
  Reachable today via A's quoted `sweep_runner.py:100`, which treats other profiles as merely
  unvalidatable rather than illegal, and via the quoted-string path (table row 20).

**Why nothing catches it.** A: `emit_jobs` materialises the full list (`sweep_jobs.py:129`) — "the one
place a collision check would be free" — and then writes `params/<name>.param` per combination, so the
later write silently wins, `runs.tsv` gains two identical lines, `n_jobs` still counts both, and
`collect_report` reads the same sentinel twice and reports two successes. Set against B's transcription
of `sweep_jobs.py:157` — "**Overwrite guard: never clobber an existing bundle**" — the module guards
the bundle against itself while silently clobbering *inside* the bundle.

**Severity: S1, exactly one.** Lens A filed four S1s (`A-01`…`A-04`); they are one defect with four
lossy inputs and one missing guard, and I have merged them. It clears the S1 bar — "corrupts a real
sweep a user runs today" — because the user-visible damage is not just a lost run: the surviving
directory is named for a physics it may not contain, and the report asserts N successes for fewer than
N executed configurations. Published figures keyed on directory name are the downstream victim.
Likelihood by input, honestly ranked:

- `densPL_alpha` (half-integer α is a normal GMC grid; B's prose only ever exemplifies integers) — **likely**;
- `sfe` sub-1% (note `sfe [0.001, 0.002]` → `sfe000` twice, from A's quoted `int(round(sfe*100)):03d`;
  inefficient-SF studies live here) — **plausible**;
- `densBE_Omega` fractional (default is 14.1, so fractional grids are natural) — **plausible**;
- `mCloud`/`nCore` 2-sig-fig mantissa — **least likely**; needs >2 sig figs of resolution, which
  decade and 4-per-decade log grids do not produce. On its own this one would be S2.

The cheap fix is not the encodings; it is the free duplicate check on the already-materialised list.

### 2. (S3) `1 < len(vs) < n` deletes the failure breakdown for the commonest sweep shape

Both lenses landed on the same line, one reading it, one reading its definition.

> **Lens A** (`sweep_jobs.py:265`): "`axes = [k for k, vs in valuesets.items() if 1 < len(vs) < n]` …
> For a one-dimensional sweep of N values over N runs, the swept key has exactly `n` distinct values,
> so `len(vs) < n` is false and the **only** axis is excluded. The function then prints just the
> return-code line — and its own header, *'Failed runs by parameter (look for a regime, not just
> indices)'*, promises the per-parameter view it just dropped."

> **Lens B** (`sweep_jobs.py:250`): "A 'swept' axis is a param that takes >1 but <n_runs distinct
> values (so per-run identifiers like path2output/model_name are excluded)." — and B's independent
> read: "in a single-axis sweep the axis has exactly `n_runs` distinct values, so the stated rule drops
> the only axis there is … it degrades exactly as the sweep gets simpler, so it is likely to look fine
> on the wide multi-axis sweeps used to test it."

**Adjudication: same defect, same line, and code and doc agree with each other.** This is *not*
doc-drift — the docstring describes the filter faithfully. It is a design defect the prose transcribes
verbatim. Blast radius: (a) every 1-D sweep, which is the modal shape; (b) any pure-tuple sweep where
each row gives a param a distinct value; (c) partially, any N-run sweep whose axis happens to have N
distinct values. It never produces wrong numbers — it deletes the diagnostic the function exists to
produce, and prints a header claiming otherwise. **S3.** B's observation that it degrades toward the
simple case (and so passes casual testing on wide grids) is the reason it has survived. Both lenses
rated S3 independently; I agree, while noting the true cost — an operator staring at a flat list of
array indices for the failure mode the function was written to surface — is worse than "misleading".

### 4. (S3→escalation) `mu_convert ~9.42e-58` — and Lens A does not mention this constant at all

**Adjudication.** A's account says the factor is *fetched from* `convert2au('m_H')`, not written as a
